    For each cell, include a citation: file path and line number or JSON key path.

    **Section 2: Disagreement Documentation**

    For each disagreement, use the template from 02-RESEARCH.md Pattern 2:

    Disagreement 1: Both vial.json rows=4 vs config.h MATRIX_ROWS=8
    - Source A: keymaps/vial_left/vial.json matrix.rows = 4
    - Source B: keymaps/vial_right/vial.json matrix.rows = 4
    - Source of truth: config.h MATRIX_ROWS = 8
    - Correct value: 8 (both vial.json files must change)
    - Why it's wrong: Split keyboard MATRIX_ROWS = physical_rows_per_side x 2. Vial uses this to compute layer_size = rows * cols * 2 bytes. With rows=4: layer_size=64; with rows=8: layer_size=128. The firmware allocates 128 bytes per layer (using the correct MATRIX_ROWS=8), so Vial reads layer 1 at byte 64 while firmware wrote it at byte 128.
    - Impact: Every layer after 0 is addressed at wrong EEPROM offset -- causes layer shift bug
    - Fix: Phase 3 (change both vial.json "rows": 4 to "rows": 8)

    Disagreement 2: Right vial.json KLE layout positions use rows 0-3 instead of 4-7
    - Source: keymaps/vial_right/vial.json layouts.keymap entries
    - Expected: Right-half keys should reference rows 4-7 (ROWS_PER_HAND offset)
    - Current: All 25 key positions use rows 0-3
    - Why it's wrong: The split keyboard's right half occupies the second half of the matrix (rows 4-7). When Vial sends a key assignment for "row 0, col 0" it writes to the left half's position, not the right half's.
    - Impact: Right-half key assignments may be written to wrong EEPROM positions
    - Fix: Phase 3 (remap all 25 right-half key positions from rows 0-3 to rows 4-7)
    - Note: Encoder KLE entries ("0,0\n...\ne" and "0,1\n...\ne") use encoder indices, NOT matrix rows. These must NOT be remapped.

    **Section 3: info.json Agreement Confirmation (MTRX-03)**

    Document the verification chain:
    1. info.json matrix_pins.rows declares 4 physical row pins
    2. info.json split.enabled = true
    3. QMK auto-doubles: 4 x 2 = 8 effective rows
    4. config.h MATRIX_ROWS = 8
    5. Result: 8 = 8, info.json agrees with config.h
    6. Conclusion: MTRX-03 is satisfied -- no fix needed for info.json

    Also note: info.json layouts.LAYOUT covers only left half (rows 0-3, 29 keys). This is correct because the data-driven LAYOUT represents one side, and keymaps use per-side macros (LAYOUT_left, LAYOUT_right). The header LAYOUT_bipedalambi was renamed to avoid data-driven conflict (verified in bipedalambi.h).
