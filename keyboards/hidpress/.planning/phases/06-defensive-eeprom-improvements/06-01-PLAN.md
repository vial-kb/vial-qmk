In BOTH keymap.c files (vial_left and vial_right), make two changes:

**Change 1: Add eeconfig_init_user() callback**

Add the following function BEFORE `keyboard_post_init_user()` (after the `load_layer_config_from_eeprom` function):

```c
void eeconfig_init_user(void) {
    // Default: all layers MODE_MOUSE (0), actuation_index = 2 (middle)
    // Encoding: bits 0-7 = layer modes (2 bits each), bits 8-10 = actuation index
    // (0 << 0) | (0 << 2) | (0 << 4) | (0 << 6) | (2 << 8) = 0x200
    eeconfig_update_user(0x200);
}
```

This overrides the weak default in quantum/eeconfig.c:28 which writes 0 (giving actuation_index=0, highest sensitivity). Our override writes 0x200 (actuation_index=2, middle sensitivity, all layers MODE_MOUSE).

Do NOT call `load_layer_config_from_eeprom()` inside `eeconfig_init_user()`. The init callback should WRITE defaults only. The boot sequence calls `keyboard_post_init_user()` -> `load_layer_config_from_eeprom()` afterward to apply them to runtime state.

**Change 2: Add EE_CLR to layer 1**

Replace ONE `KC_TRNS` on layer 1 with `EE_CLR`:

- **Left half (vial_left/keymap.c):** Replace the LAST `KC_TRNS` in layer 1 (position k17, the bottom-right key that is KC_DOWN on layer 0) with `EE_CLR`. In the layer 1 LAYOUT_left call, change the final `KC_TRNS` to `EE_CLR`.

- **Right half (vial_right/keymap.c):** Replace the LAST `KC_TRNS` in layer 1 (position k31, the bottom key that is MO(1) on layer 0) with `EE_CLR`. Wait -- k31 is MO(1) itself, and MO(1) is a momentary layer key. When holding MO(1), the key at k31 on layer 1 is what would be triggered. Since the user is already holding MO(1) at k31, pressing k31 again is the same physical key. This means EE_CLR at k31 on layer 1 would require pressing the SAME key that activates the layer -- which is impossible (it is already held). Instead, use position k35 (the second-to-last parameter in LAYOUT_right, which is KC_EQL on layer 0). In the layer 1 LAYOUT_right call, change the second-to-last `KC_TRNS` to `EE_CLR`.

For clarity on LAYOUT_right parameter order:
```
k03, k04, k02, k05, k01, k00, k13, k14, k12, k15, k11, k10, k23, k24, k22, k26, k25, k21, k20, k36, k33, k34, k32, k35, k31
```
The 24th parameter (second-to-last) is k35 = KC_EQL on layer 0. Replace this KC_TRNS with EE_CLR.

After changes, both layer 1 definitions will have exactly one EE_CLR and the rest KC_TRNS.

<task type="auto">
  <name>Task 2: Create EEPROM clear procedure documentation</name>
  <files>bipedalambi/EEPROM-CLEAR-PROCEDURE.md</files>
  <action>
Create `bipedalambi/EEPROM-CLEAR-PROCEDURE.md` documenting the EEPROM clear procedure for both halves. This file lives alongside the firmware code (not in .planning/) because it is a permanent reference for the user.

The document must cover:

**1. Overview:** Each half has independent EEPROM. Clearing one half does NOT clear the other. Both halves must be cleared separately.

**2. Method 1: QK_CLEAR_EEPROM (EE_CLR) key**
- Available on layer 1 of both halves (placed in PROGMEM, survives EEPROM clear)
- Left half: Hold MO(1) (at KC_MINS position, layer key in bottom thumb row) + press the key at the KC_DOWN position (bottom-right, k17)
- Right half: Hold MO(1) (at the bottom position, k31) + press the key at the KC_EQL position (k35, adjacent to MO(1))
- Behavior: EEPROM is invalidated, keyboard performs a soft reset (USB disconnect/reconnect), boots with defaults (middle actuation, all layers mouse mode)
- Note: This only clears the half that is currently connected via USB

**3. Method 2: Bootmagic Lite (hold key while plugging in)**
- Left half: Hold KC_ESC while plugging in USB. Clears EEPROM and enters bootloader (DFU mode). Flash firmware or power cycle to boot normally.
- Right half: Hold KC_BSPC while plugging in USB. Same behavior.
- Note: Bootmagic jumps to bootloader after clear (unlike EE_CLR which does a soft reset). The user must flash firmware or unplug/replug to boot normally.

**4. After clearing:** Both methods result in `eeconfig_init_user()` running on next boot, which sets actuation_index=2 (middle sensitivity) and all layers to MODE_MOUSE. The Vial dynamic keymap is also reset to PROGMEM defaults. Any keys customized in Vial will need to be reconfigured.

**5. When to clear EEPROM:**
- After flashing firmware with changed EEPROM layout (matrix dimension changes, etc.)
- If the keyboard behaves unexpectedly (wrong actuation, wrong layer modes)
- If Vial shows incorrect layer content

**6. Full reset procedure for both halves:**
- Step 1: Connect left half via USB
- Step 2: Clear EEPROM on left half (Method 1 or 2)
- Step 3: Disconnect left half
- Step 4: Connect right half via USB
- Step 5: Clear EEPROM on right half (Method 1 or 2)
- Step 6: Reconnect normally and reconfigure in Vial if needed
  </action>
