**config.h changes (add after the existing pointing device section, near line 67):**

1. Add `#define POINTING_DEVICE_AUTO_MOUSE_ENABLE` -- this activates QMK's auto mouse feature which automatically activates a layer when the pointing device reports movement.

2. Add `#define AUTO_MOUSE_DEFAULT_LAYER 3` -- use layer 3 as the auto mouse target layer. Layer 1 is already used by MO(1) for the function layer, so layer 3 avoids conflict. The user can remap layer 3 keys in Vial to mouse buttons (left click, right click, etc.) for when the trackpad is in use.

3. Add `#define AUTO_MOUSE_TIME 650` -- 650ms timeout before the auto mouse layer deactivates after movement stops. This is the QMK default and provides a good balance.

4. Add `#define AUTO_MOUSE_THRESHOLD 10` -- minimum movement threshold to activate the layer. Prevents accidental activation from noise.

**keymap.c changes:**

1. Add `pointing_device_init_user()` function after `keyboard_post_init_user()`:
```c
void pointing_device_init_user(void) {
    set_auto_mouse_enable(true);
}
```

2. Update `pointing_device_task_user()` -- the TPS43 azoteq_iqs5xx driver handles all gestures internally (taps, scroll, swipe) in its get_report function. The driver outputs:
   - x/y for single-finger cursor movement
   - h/v for two-finger scroll
   - buttons for taps, swipes, press-and-hold

   The old code in this function was designed for the analog_joystick driver and intercepted reports based on MODE_MOUSE/MODE_SCROLLING/MODE_CUSTOM_KEYS. With the driver switched to TPS43, this function now receives TPS43 data -- not joystick data. The joystick reads are handled separately in matrix_scan_user() for custom keys mode.

   Replace the existing `pointing_device_task_user` body with a pass-through that just registers OLED activity and returns the report unchanged:
```c
report_mouse_t pointing_device_task_user(report_mouse_t mouse_report) {
    if (mouse_report.x != 0 || mouse_report.y != 0) register_oled_activity();
    return mouse_report;
}
```
   This lets the TPS43 driver's gesture handling work correctly: cursor movement, scroll, taps, and swipes all flow through unmodified. The old MODE_SCROLLING accumulator logic is no longer needed because the TPS43 driver produces h/v scroll values directly.

3. Remove the now-unused scroll state variables at the top of keymap.c:
   - Remove `#define SCROLL_DIVISOR_H 24.0`
   - Remove `#define SCROLL_DIVISOR_V 24.0`
   - Remove `float scroll_accumulated_h = 0;`
   - Remove `float scroll_accumulated_v = 0;`
   - Remove `bool scroll_inverted = false;`

   Also remove the `SCROLL_DIR` case from `process_record_user` since scroll direction is now handled by the TPS43 hardware/driver, not firmware.

4. Do NOT modify `matrix_scan_user()` -- the joystick custom keys mode still works independently via direct ADC reads.

5. Do NOT modify the `layer_state_set_user()` function -- it still correctly switches `current_mode` per layer (used by OLED display and joystick behavior). The auto mouse layer system manages its own layer activation independently from this.

**Important: Do NOT remove the MODE_MOUSE/MODE_SCROLLING/MODE_CUSTOM_KEYS enum or the TMB_MODE cycling logic.** These are still used by the joystick (custom keys mode in matrix_scan_user) and OLED display. Phase 15 will refactor these.
