  <name>Task 1: Switch pointing device driver and update build/hardware config</name>
  <files>
    keyboards/hidpress/bipedalambi/rules.mk
    keyboards/hidpress/bipedalambi/config.h
  </files>
  <action>
    **rules.mk changes:**
    1. Change `POINTING_DEVICE_DRIVER = analog_joystick` to `POINTING_DEVICE_DRIVER = azoteq_iqs5xx`
    2. Keep `SRC += analog.c` -- this is still required because `matrix_scan_user()` in keymap.c calls `analogReadPin(GP28)` and `analogReadPin(GP29)` for joystick custom keys mode. The analog_joystick pointing driver previously set ANALOG_DRIVER_REQUIRED which pulled in analog.c; with azoteq_iqs5xx the build system sets I2C_DRIVER_REQUIRED instead, so we must keep the explicit SRC line for ADC reads.
    3. Keep `JOYSTICK_ENABLE = yes` and `JOYSTICK_DRIVER = analog` -- joystick hardware still exists on left half for custom keys/scroll modes.

    **config.h changes:**
    1. Remove ALL `ANALOG_JOYSTICK_*` defines (lines 65-73): `ANALOG_JOYSTICK_AUTO_AXIS`, `ANALOG_JOYSTICK_SPEED_REGULATOR`, `ANALOG_JOYSTICK_CUTOFF`, `ANALOG_JOYSTICK_X_AXIS_PIN`, `ANALOG_JOYSTICK_Y_AXIS_PIN`, `ANALOG_JOYSTICK_ENABLE`. These were configuration for the analog_joystick pointing driver which is no longer used. The joystick ADC reads in matrix_scan_user() use `analogReadPin()` directly and do not depend on these defines.
    2. Change `POINTING_DEVICE_LEFT` to `POINTING_DEVICE_RIGHT` -- the trackpad is on the right half, not the left.
    3. Remove `POINTING_DEVICE_INVERT_X` -- this was for the analog joystick driver. Axis orientation for the TPS43 is configured differently (via `azoteq_iqs5xx_set_xy_config()` in a later phase).
    4. Add `#define AZOTEQ_IQS5XX_TPS43` in the pointing device section -- this tells the driver to use TPS43 resolution (2048x1792 for 43x40mm pad). Add it unconditionally (not inside `#ifdef RIGHT_SIDE`) because the driver header needs it at compile time for both halves when split pointing is enabled.

    **I2C coexistence verification (no code changes needed, document in commit):**
    - Right half: OLED at I2C address 0x3C, TPS43 at I2C address 0x74 -- no collision
    - Both devices share I2C1 (GP18 SDA, GP19 SCL) on the right half
    - Left half: OLED at I2C0 (GP12 SDA, GP13 SCL) -- no trackpad, no conflict
    - The QMK I2C master driver handles bus arbitration; both devices are polled at different addresses
    - mcuconf.h already enables both I2C0 and I2C1, no changes needed
    - halconf.h already has HAL_USE_I2C TRUE, no changes needed
  </action>
  <verify>

    Inspect config.h and confirm: no ANALOG_JOYSTICK_* defines, POINTING_DEVICE_RIGHT (not LEFT), AZOTEQ_IQS5XX_TPS43 defined, SPLIT_POINTING_ENABLE still defined.
  </verify>
