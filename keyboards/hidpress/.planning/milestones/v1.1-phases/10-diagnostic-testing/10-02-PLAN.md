  <name>Task 1: Switch to half-duplex mode and compile both halves</name>
  <files>
    keyboards/hidpress/bipedalambi/config.h
  </files>
  <action>
    **DIAG-02: Half-duplex fallback (Hypothesis H3 -- diagnostic tool)**

    1. Edit `config.h` -- comment out the full-duplex define:
       - Change line 6 from: `#define SERIAL_USART_FULL_DUPLEX`
       - To: `// #define SERIAL_USART_FULL_DUPLEX  // DIAG-02: disabled for half-duplex test`
       - Do NOT remove it entirely -- comment it out so it can be restored easily

    **What this changes in the serial driver (serial_vendor.c):**
    - Without SERIAL_USART_FULL_DUPLEX, the driver uses half-duplex mode
    - Half-duplex uses only the TX pin for bidirectional communication
    - The TX pin switches between output (transmitting) and input (receiving)
    - The RX pin (GP1 on left, GP16 on right) is completely unused
    - Only ONE data wire is needed on the TRRS cable (TX pin from each half)
    - This means LEFT GP0 must connect to RIGHT GP17 (TX-to-TX, single wire each direction)

    **Important: RX pin defines stay in config but are ignored by the driver in half-duplex mode. No need to remove SERIAL_USART_RX_PIN defines from keymap config.h files.**

    2. Compile both halves from repo root:
       `qmk compile -kb hidpress/bipedalambi -km vial_left`
       `qmk compile -kb hidpress/bipedalambi -km vial_right`

    3. Report file paths and sizes. UF2 sizes may be slightly smaller than DIAG-00 build (half-duplex PIO program is simpler).
  </action>
  <verify>
    1. `grep "SERIAL_USART_FULL_DUPLEX" keyboards/hidpress/bipedalambi/config.h` shows commented-out line
    2. Both UF2 files exist with fresh timestamps
    3. No compilation errors
  </verify>
  <done>config.h has SERIAL_USART_FULL_DUPLEX commented out. Both halves compile cleanly in half-duplex mode.</done>
