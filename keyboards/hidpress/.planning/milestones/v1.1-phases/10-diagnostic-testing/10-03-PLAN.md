  <action>
    **Read the 10-02-SUMMARY.md first** to determine which path to take.

    ---

    **PATH A: DIAG-02 reported PASS (half-duplex worked = wiring issue)**

    The problem is confirmed as TX/RX wiring. Full-duplex needs crossed wiring (Left TX -> Right RX, Left RX -> Right TX), but the TRRS cable likely has straight-through routing. Apply DIAG-04 (PIN_SWAP test):

    1. Edit `config.h`:
       - Uncomment `SERIAL_USART_FULL_DUPLEX` (restore line 6 to: `#define SERIAL_USART_FULL_DUPLEX`)
       - Add directly after it: `#define SERIAL_USART_PIN_SWAP  // DIAG-04: test straight-through TRRS wiring`

    What PIN_SWAP does in serial_vendor.c (lines 442-446):
    - Master init calls `pio_init(rx_pin, tx_pin)` instead of `pio_init(tx_pin, rx_pin)`
    - This makes the master TRANSMIT on its RX pin and RECEIVE on its TX pin
    - Effect: Left transmits on GP1 (normally RX), receives on GP0 (normally TX)
    - If TRRS has straight-through wiring (Left GP0 -> Right GP17, Left GP1 -> Right GP16), this matches

    Also request DIAG-03 (wiring verification) from user in the checkpoint.

    2. Compile both halves:
       `qmk compile -kb hidpress/bipedalambi -km vial_left`
       `qmk compile -kb hidpress/bipedalambi -km vial_right`

    ---

    **PATH B: DIAG-02 reported FAIL (half-duplex also failed = not wiring)**

    Wiring is ruled out. Try DIAG-05 (MASTER_LEFT) to eliminate USB detection as a variable:

    1. Edit `config.h`:
       - Uncomment `SERIAL_USART_FULL_DUPLEX` (restore line 6 to: `#define SERIAL_USART_FULL_DUPLEX`)
       - Comment out `SPLIT_USB_DETECT`: change to `// #define SPLIT_USB_DETECT  // DIAG-05: disabled for MASTER_LEFT test`
       - Add after it: `#define MASTER_LEFT  // DIAG-05: hardcode left as master`

    What MASTER_LEFT does:
    - Hardcodes the left half as always-master, right as always-slave
    - Eliminates VBUS detection timing as a variable
    - The user MUST always plug USB into the LEFT half for this test

    2. Compile both halves:
       `qmk compile -kb hidpress/bipedalambi -km vial_left`
       `qmk compile -kb hidpress/bipedalambi -km vial_right`

    ---

    **PATH C: DIAG-02 reported PARTIAL**

    Read the 10-02-SUMMARY.md carefully for the user's description. Based on the partial behavior:
    - If one direction works (e.g., master->slave OK, slave->master fails): likely wiring issue on one data line. Follow PATH A.
    - If intermittent: could be signal integrity. Follow PATH B but note the intermittent behavior.
    - If other: use best judgment based on the partial description.
  </action>
